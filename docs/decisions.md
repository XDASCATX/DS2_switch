# Принятые решения

Формат: решение — почему — когда — что из этого следует. «Владелец» — владелец проекта (решение его);
«исполнитель» — техническое решение по ходу работы.

| # | Решение | Почему | Когда / кто | Следствия |
|---|---|---|---|---|
| D1 | Статическая рекомпиляция (ReXGlue) на базе SDK nfsmw-nx, а не эмулятор | у nfsmw-nx уже рабочий Switch-слой и сборка | 2026-10-19, исходное ТЗ | весь код игры — `app/generated`, правки поведения — через SDK/overrides/хуки |
| D2 | Только Xbox 360-версия, файлы — копия владельца; `Default.xex` не менять; ничего из игры не коммитить | ТЗ и право | ТЗ, владелец | `.gitignore`; `audit/` хранит только хеши |
| D3 | Overrides codegen — только из подтверждённых данных (разбор по инструкциям) | ошибки рекомпиляции дорогие и тихие | 2026-10-19, владелец | `config/ds2_overrides.*.toml` с комментариями; `tools/huecos.py` |
| D4 | Тулчейн Switch из исходников | серверы devkitPro/rustup недоступны из среды | 2026-10-20, исполнитель | `tools/switch/toolchain/`; Mesa только с патчем `mesa-switch-ds2-perf.patch` |
| D5 | Гостевая память Switch выровнена по 2 МБ, гранула 2 МБ, стеки 6 МБ, nvservices 64 МБ | 2001-0103 и нехватка кучи (тесты 12–21) | 2026-10-20 | значения в TOML/умолчаниях приложения |
| D6 | Тестовые переключатели — через TOML, не через меню | воспроизводимость | владелец | каждый эксперимент = ключ TOML с откатом |
| D7 | «Исправлено/работает» — только после теста на Switch; замеры отделять от предположений | ПК (lavapipe) не говорит о скорости и памяти консоли | владелец | [testing.md](testing.md), [experiments.md](experiments.md) |
| D8 | Не жертвовать правильностью графики ради кадров; целые этапы рендера не выключать без доказательства | качество | владелец | A/B-ключи вместо выключения проходов |
| D9 | Прошлые версии (NRO, TOML) не перезаписывать | сравнимость | владелец | `package-release.sh` отказывается перезаписать `releases/vNN` |
| D10 | Разработка в ветке `diag/switch-level-load`; `main` — только для публичного выпуска по явному запросу | владелец | изменено 2026-10-23 для 0.56 | код готовить в рабочей ветке, затем переносить в `main` с англоязычным публичным README |
| D11 | **Свой (нативный) рендерер вместо оптимизации эмуляции EDRAM**; эмуляция остаётся fallback | эмуляция упёрлась в переносы EDRAM (v50: 11–16 кадр/с) | 2026-10-22/23, владелец | `sdk/src/graphics/native/`; `ds2_native_renderer` |
| D12 | Нативный рендерер на Vulkan/NVK, шейдеры — переводчиком SDK во время игры (не deko3d, не офлайн-библиотека сразу) | deko3d/uam нет в тулчейне; NVK уже работает; переводчик проверен на DS2 | v51, исполнитель | офлайн-библиотека — следующий шаг ([handoff/18-native-renderer-study](handoff/18-native-renderer-study.md)) |
| D13 | MSAA в пространстве сэмплов (4x 640×360 = изображение 1280×720) | DS2 переинтерпретирует одни и те же области EDRAM как 1x и 4x; так они — одно изображение | v51, исполнитель | цена: шейдинг 4x-целей ×4 (см. performance.md §6) |
| D14 | На старую эмуляцию сил не тратить; один TOML для тестов | просьба владельца | 2026-10-23, владелец | `ds2.toml` = нативный рендерер; эмуляционный TOML — `15-ds2.toml.v54_emulation` |
| D15 | Частоты сессии ставит игра (override sysmodule), цель — лёгкий профиль | раньше — вручную, предельный разгон | 2026-10-23, владелец | `ds2_switch_cpu/gpu/mem_mhz`; снижать по мере оптимизации |
| D16 | Occlusion queries — «всегда видно» | настоящие запросы с запаздыванием вызвали мигание врагов | v55, исполнитель по отзыву | `ds2_native_occlusion_queries = false` |
| D17 | Документация — точка входа `CLAUDE.md`, состояние — `docs/HANDOFF.md`, обновлять при каждой версии | передача между ИИ | 2026-10-23, владелец | [README.md](README.md) |
| D18 | Тестовый выпуск 0.56 = v56: тот же код и TOML (CPU 1963 / GPU 1267, подробный профиль), отдельный NSP-forwarder, англоязычные README/описание релиза в `main`; GitHub-репозиторий оставить PRIVATE | первый релиз-кандидат для тестирования, запуск без Sphaira; владелец выбрал ограниченный доступ | 2026-10-23, владелец | не выдавать за консольно проверенный или общедоступный; `prod.keys`, оригинальную иконку и бинарники не коммитить; только метаданные/иконка релизного NRO меняются |

Ранние правила (2026-10-19, [handoff/01](handoff/01-status-and-rules.md)) требовали отдельного согласия на правки SDK
и повторный codegen. **Контекст из переписки:** с этапа рендерера владелец сам поставил задачи, требующие правок SDK
(нативный рендерер, оптимизации), и codegen перезапускался в рамках задач v46/v49. Перегенерация кода — часы работы;
делать только когда без неё нельзя, и предупреждать владельца.
