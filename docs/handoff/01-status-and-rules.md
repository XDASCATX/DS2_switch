# 01. Состояние проекта и правила работы

## Что сделано и подтверждено

1. **Изучен NFSMW-NX.** Приложение под GPL-3.0, каталог `sdk/` (ReXGlue на базе Xenia + слой Horizon для Switch) под BSD-3 — переиспользовать SDK и инструменты можно. В репозитории есть гайд `docs/porting-another-game.md`: сначала ПК-сборка, потом Switch, потом нативный рендерер и заранее переведённые шейдеры.
2. **Создана отдельная рабочая папка** с собственным Git, в неё скопированы `sdk/` и `tools/` из NFSMW-NX. Оригинальный репозиторий не изменялся.
3. **Собран host-бинарник `rexglue`** (Linux x86-64, clang 20 + libstdc++ 13). `--help`/`--version` возвращают 0. Подробности — `02`.
4. **Разобран `Default.xex`.** Это настоящий XEX2 Xbox 360, title ID `465307E4`, не delta-патч, формат поддерживается загрузчиком ReXGlue. Подробности — `03`.
5. **Первый прогон `rexglue codegen`.** XEX загрузился и расшифровался, все фазы анализа пройдены, валидация упала: 50 переходов `b` в адреса, не принадлежащие ни одной функции. C++ не сгенерирован. Подробности — `04`.
6. **Разобраны все 50 ошибок по инструкциям** с помощью собственного дампа образа и дизассемблера. Классификация и предложенный фикс — `05`.

## Чего нет / что не проверялось

- Ни одна строка игрового кода ещё не рекомпилирована; ничего не запускалось.
- Сборка под Switch (devkitPro/devkitA64) не настраивалась; в облачной песочнице её нет, и ресурсов не хватит (см. `07`).
- Версия игры «1.10» и Calibration 1.15 по заголовку **не подтверждены**: XEX — базовый, без title update.
- Причина, по которой GapFill не подхватил эти участки, — гипотеза по исходникам, не подтверждена trace-логом (см. `05`).

## Правила и договорённости с владельцем проекта

Из исходного ТЗ:
- Меньше отчётов, больше работающего кода; итерации «изменить → собрать → проверить → закоммитить».
- Обычные безопасные действия по разработке — без согласования.
- Только Xbox 360-версия; не подменять PC/Xbox One.
- Не обходить DRM, не скачивать нелегальные копии. Игровые файлы предоставляет владелец из своей копии.
- Не заявлять о достижении этапа без проверяемого результата.
- Игровые файлы запрашивать одним конкретным сообщением.

Договорённости, появившиеся по ходу работы (действуют сейчас):
- **Не изменять исходный `Default.xex`.** Работать с копией в `assets/game_root/`, проверять хэш.
- **Не трогать оригинальный `nfsmw-nx`.**
- **Изменения в исходниках SDK — только с отдельного согласия.** Предпочтение — overrides в манифесте вместо патчей SDK.
- **Не создавать манифест/overrides наугад**, только из подтверждённых данных.
- **Повторный запуск codegen — только с отдельного согласия.**
- Для 50 ошибок выбран «вариант 2»: сначала исследовать по инструкциям, потом предлагать минимальный фикс, а не объявлять все цели функциями вслепую.
