## Прогон codegen 3 (trace, без overrides)

`rexglue --log-level trace --log-file … codegen app/ds2_manifest.toml`. Exit 1, те же 50 ошибок, 6:35. Полный stdout — 118 МБ (у владельца: `SW1_ds2/logs/2026-10-19/codegen-trace.log.gz`). Файл из `--log-file` ротируется по 5 МБ (20 файлов), начало теряется — для анализа брать stdout.

Счётчики: 43 723 регионов Scan, 97 204 `split segment`, 19 280 `registered`, удалено 1 933 поглощённых GAP_FILL.

### Подтверждённая причина (trace + исходник)

- Scan (`phase_scan.cpp`) режет `.text` на регионы только по нулевым словам.
- GapFill (`phase_gapfill.cpp`, `splitRegionOnTerminators`) режет регион только на `blr` (точная кодировка `0x4E800020`, `Instruction::is_return`) и на `b` к функции, которая известна **до** GapFill. Набор `knownCallables` строится один раз до цикла.
- Перед каждой из 50 точек входа стоит инструкция, по которой разреза нет: **40 раз — `b` к адресу, ещё не известному как функция** (в том числе к адресам, которые GapFill регистрирует позже в том же прогоне), **10 раз — `bctr`**.
- Поэтому точка входа оказывается в середине сегмента. Поиск блоков от начала сегмента останавливается на первом переходе, и цель не принадлежит ни одной функции. Для 44 целей это видно напрямую: ближайшая функция — 1 блок, который кончается ровно перед целью (например, `sub_823A4740: 1 block, 2 instructions`, цели на `+8…+0x20`).
- Судьба начала сегмента: 25 — GapFill, SEALED; 11 — функция существовала до GapFill; 8 — GapFill зарегистрировал, но в итоговом графе её нет; 5 — сегмент начинается внутри функции PDATA и пропущен; 1 — начало внутри функции из Discover.
- Все 15 хвостовых целей адаптеров зарегистрированы GapFill ровно по своим адресам и есть среди SEALED.

Разбивка по каждой цели — `data/trace-unresolved-causes.tsv` и `data/trace-unresolved-match.tsv`; скрипты — `tools/ds2_trace_match.py`, `ds2_trace_nodes.py`, `ds2_trace_cause.py`.

### Следствие для исправления

Записи `[functions]` регистрируются первыми (`FunctionAuthority::CONFIG`), значит, объявленные точки входа войдут в `knownCallables` и переходы к ним начнут резать сегменты. Это вывод из исходника; проверить можно только прогоном с overrides. Альтернатива — изменить правила разреза в SDK, это только с отдельного согласия владельца.
