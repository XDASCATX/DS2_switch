# 16. Оптимизация GPU на Switch от v30

База — v30 (`15-ds2.toml.v30`, NRO diag14): MODE 7 как `render_target_transfer_skip = 1`, ~3–5 кадр/с, правильные
цвета. Каждая итерация — отдельная папка `SW1_ds2/switch/vNN*` и `releases/vNN*`; v30 не меняется.

## v31-diag: измерители (без смены поведения рендеринга)

- `gpu_zone_timing` (cvar SDK, по умолчанию выкл.): timestamp-запросы (`vkCmdWriteTimestamp`, BOTTOM_OF_PIPE) вокруг
  зон — переносы владения + очистки resolve (`PerformTransfersAndResolveClears`), resolve (`Resolve`), загрузка
  текстур (dispatch в `texture_cache.cpp`), вывод (гамма/FXAA) — и вокруг всей отправки. Пул на 8 отправок × 1024
  запросов; результаты читаются без ожидания, когда fence отправки уже сигнален. Тики NVK × 1,627 нс
  (nfsmw-nx `measuring.md`). Зоны могут быть вложенными (очистки внутри resolve) — сумма может превышать итог.
- новые счётчики: render pass (52), барьеры (53), проходы по сэмплам MSAA в переносах (49), host depth store —
  dispatch (50) и пиксели (51); переносы: RT глубины/цвета/MSAA (39–41), draw глубины/битов stencil/цвета/
  пропущенные (35–38), пиксели × реально нарисованные проходы (33–34).
- Отчёт `rex_perfil.log`: строки `transferencias detalle`, `pasadas de render … barreras …`,
  `GPU ms por envio medido: total | transferencias | resolves | carga de texturas | salida | resto`.
- В `DeferredCommandBuffer` добавлен `CmdVkWriteTimestamp`; в таблицу функций устройства — `vkCmdWriteTimestamp`,
  `vkGetQueryPoolResults`.
- ПК: GPU-плагин — отдельная библиотека `librexgpu-xenos.so`, цель `ds2` её не пересобирает: после правок в
  `sdk/src/graphics` собирать и `--target rexgpu-xenos` (иначе несовпадение структур → «Failed to create the 512 MB
  Vulkan buffer»). На Switch плагин статический и пересобирается вместе с NRO.
- Сборка: `releases/v31-diag`, sha256 `3960a1ea…6dc9`; `SW1_ds2/switch/v31_diag/{ds2.nro,ds2.toml}`;
  конфигурация — `15-ds2.toml.v31-diag` (= v30 + `gpu_zone_timing = true`). ПК: run36 без новых ошибок.

## v31-diag на консоли (diag_toml31): куда уходит GPU

GPU 1228,8 МГц (разгон), в мире ~2,7–3,5 кадр/с; в меню 39–47 кадр/с. На кадр (одна отправка) — среднее по 10-с
отчётам в мире:

| | значение |
|---|---|
| GPU всего | 286–364 мс |
| переносы владения (зона) | 105–188 мс |
| resolve (зона, 25–60 шт., 12–16 экранов) | 32–54 мс |
| загрузка текстур | 4,5–6,6 мс |
| вывод | ~0 |
| остальное (draw игры и пр.) | 48–220 мс |
| RT-получатели переносов | глубина 21–25, цвет 13–34, из них MSAA 12–13 |
| transfer-draw | глубина 35–49, цвет 20–49; пропущено проходов по битам stencil 250–360 |
| пиксели переносов × проходы | глубина 21–24 экрана, цвет 14–20 экранов (без множителя сэмплов MSAA) |
| render pass / барьеры | 120–200 / 330–610 на кадр |
| draw игры | 520–860, площадь scissor 230–565 экранов |

Переносы — ~40 экранов пикселей за 105–188 мс (~250 Мпикс/с) — в десятки раз медленнее заливки: каждый
фрагмент переноса считает адрес в EDRAM, читает источник (`texelFetch`) и конвертирует формат; для MSAA-получателей
включён `sampleShadingEnable` (шейдер на каждый сэмпл). Барьеров ~3 на перенесённый RT.

v31b-diag: те же измерения + зоны «transfer-draw в глубину», «transfer-draw в цвет», «барьеры» (GPU-слив, который
они вызывают), «draw игры» (с числом экземпляров и мкс на штуку), счётчик draw в MSAA-RT; 4096 timestamp на
отправку. `releases/v31b-diag` (sha256 `63f71d2a…3d72`), `SW1_ds2/switch/v31b_diag/`. Timestamp на каждый draw
сам добавляет сериализацию — абсолютные цифры будут чуть выше, важны доли.

## v31b на консоли (diag_toml31b): виновник — transfer-draw в глубину

В мире на кадр (~350 мс GPU): transfer-draw в глубину **44 × 3,4 мс = 150 мс**, в цвет 45 × 1,3 мс = 58 мс,
resolve 55 × 1,2 мс = 65 мс, draw игры 675 × 0,07 мс = 46 мс, загрузка текстур 9 мс, барьеры ~0 (500 шт. —
дёшевы). Итого переносы ≈ 60 % GPU, из них 70 % — в глубину.

## Почему столько переносов (ПК, тот же поток команд игры)

Гистограмма и покадровая трасса переносов на ПК (`rt_transfer_stats`, `rt_transfer_trace`, cvar для разработки):
~110 переносов и ~41 экран пикселей на кадр в мире, и **74 % площади (85 % в глубину) вызывают draw-очистки**
игры: `prim 8 n 3` (rectangle list = D3D Clear), глубина ALWAYS с записью или цвет с маской FFFF, без
отсечения (clip_disable) и со scissor 8192×8192. Для таких draw ReXGlue по умолчанию не исполняет вершинный
шейдер на ЦП (`execute_unclipped_draw_vs_on_cpu = false`; в xenia по умолчанию true — «otherwise up to the
entire EDRAM may be considered used … spurious EDRAM range ownership transfer round trips»), поэтому высота RT
считается до конца EDRAM (переносы `tiles 0..2048`), а затем всё перенесённое сразу стирается очисткой.
Пример цепочки: тени рисуются в 4×MSAA-глубину и перечитываются как 1× цвет (известный приём Xbox 360) — каждый
проход начинается с очистки, перед которой копируется вся старая EDRAM.

## v32: перенос не делается, если draw его целиком перезаписывает

- `render_target_transfer_elide_overwritten` (SDK, `vulkan/render_target_cache.cpp`): перед переносами
  `VulkanRenderTargetCache::ComputeDrawOverwrite` проверяет draw, который привязывает RT: нет `kill`/alpha
  test/alpha-to-mask; глубина — z_enable+z_write+ALWAYS (stencil: ALWAYS+REPLACE+маска FF, иначе проходы stencil
  должны быть и так выключены `render_target_transfer_skip & 1`); цвет — все компоненты пишутся, смешивание
  ONE/ZERO/ADD. Затем `DrawExtentEstimator::EstimateFullyCoveredRectangle` исполняет вершинный шейдер на ЦП
  (3–6 вершин) и доказывает, что draw — один прямоугольник по осям (rectangle list 3, quad list / strip 4,
  triangle list 6: все вершины — углы bbox, площадь треугольников = площадь bbox), берёт только целиком
  покрытые пиксели (все сэмплы MSAA) и пересекает со scissor. Перенос пропускается, только если все его
  прямоугольники внутри. Картинка та же: эти пиксели draw перезапишет до любого чтения.
- `execute_unclipped_draw_vs_on_cpu = true` (существующий cvar): высота RT для очисток — по их вершинам, а не до
  конца EDRAM; без этого прямоугольники переносов выходят за очистку и не пропускаются.
- ПК (lavapipe), тот же сценарий до мира, `rt_transfer_stats`: в мире без правок (run40) переносится ~600 тайлов
  EDRAM на каждое обновление RT-получателя, с обеими правками (run44) — ~178, т. е. площадь переносов меньше в
  ~3,4 раза. Основная доля — `execute_unclipped_draw_vs_on_cpu` (очистки перестали «занимать» EDRAM до конца);
  сама элизия добавляет ~1,5 экрана на кадр. На ПК картинка сравнивалась только визуально (сцена тёмная, как и
  раньше на ПК); точная проверка — на консоли.

### Проверка кода v32 перед выпуском (2026-10-21)

Работа v32 была прервана до выпуска; при проверке найдены и исправлены условия, при которых пропуск переноса
мог бы испортить картинку:
- цвет считался перезаписанным без проверки теста глубины/stencil — если тест может не пройти, цвет там не
  пишется. Теперь пропуск только при `!z_enable || zfunc ALWAYS` и `!stencil_enable || stencilfunc ALWAYS`
  (с обеих сторон);
- глубина считалась перезаписанной при stencil-тесте не ALWAYS — исправлено тем же условием;
- область draw не учитывала отсечение клиппером (вьюпорт/ближняя-дальняя плоскости/пользовательские плоскости):
  теперь требуется `PA_CL_CLIP_CNTL.clip_disable` и выключенные пользовательские плоскости (очистки игры
  идут именно так).
Сборка: `releases/v32` sha256 `cee2059c…c1ae`, `SW1_ds2/switch/v32/{ds2.nro,ds2.toml}`; недовыпущенная сборка с
ошибками условий сохранена как `releases/v32-prefix-unreleased` (не передавалась). Лишняя папка `SW1_ds2/switch/v31`
(NRO `c5e37dfe…`, toml = v30) от прерванной попытки перенесена в `_to_delete/stray_v31_c5e37dfe`.
ПК: run52 (50 с, обе правки) без новых ошибок.

Ожидание на консоли (по v31b): переносы ~210 мс/кадр; при сокращении площади в ~3–3,5 раза — ~60–70 мс, итого
GPU ~350 → ~200 мс/кадр, т. е. порядка 4–6 кадр/с, а не 30. Подтверждать замером (в toml оставлен
`gpu_zone_timing = true` — то же, что в v31b, для сравнения долей).
