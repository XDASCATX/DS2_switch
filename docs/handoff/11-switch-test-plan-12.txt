DS2 Switch - build diag12 (branch diag/switch-level-load): tests 19 and 20 (replaces diag11)
=========================================================================

What changed and why
  Every failure so far was 2001-0103 at the start of the level load, after which other system parts (file writes,
  HOME, the overlay) failed too. Under hbloader the game process has NO system resource of its own (the log shows
  sysres_kb=0/0). Such a process takes its kernel page tables from one heap the kernel shares with all system
  processes (Atmosphere: Kernel::InitializeResourceManagers, s_page_table_heap). Running that heap dry gives exactly
  2001-0103 for everyone. Real games carry their own system resource in their NPDM; hbloader's NPDM has none.

  1. hbl_ds2.nsp: the official nx-hbloader v2.4.5, rebuilt with ONE change in its NPDM: system_resource_size =
     64 MB. The game then takes page tables from its own 64 MB instead of the shared heap. Other homebrew launched
     through it gets 64 MB less heap and otherwise behaves the same.
  2. ds2.nro, guest memory (the SDK part that recreates the Xbox 360 memory): it now asks for far fewer page
     tables. The guest window and its code alias were placed at random 4 KB addresses (libnx's virtmemFind* takes
     a guard size, not an alignment), and memory was committed in hundreds of small pieces; both force a page
     table for every 2 MB. Now the window and the alias are 2 MB aligned and memory is committed in 2 MB pieces.
     Simulated on the PC with the game's real allocation sequence: 2103 -> 512 page tables (8.2 -> 2.0 MB), and
     the remaining 512 are mostly the simulation's own worst case of write watches.
     So test 20 (stock hbloader) may now pass too: then the special hbloader is not needed at all.
  3. ds2.nro: new heartbeat fields
       pt_left>=32 / pt_left=K (code)  how many more page tables the kernel can still give (probe, 32 max)
       pt_win=A/B                      2 MB windows of the address space that need a page table (min/max)
       sysres_kb=U/T                   own system resource used/total (stays 0/0 with the stock hbloader)
       chunks=N                        guest memory pieces (expected ~250-400)

Preparation
  - Keep the current sdmc:/switch/ds2/ds2.nro: rename it to ds2_diag10.nro. Copy ds2.nro from this folder (diag12).
  - Copy ds2.toml.test19 as sdmc:/switch/ds2/ds2.toml.
  - Copy hbl_ds2.nsp to sdmc:/atmosphere/hbl_ds2.nsp. Do NOT touch sdmc:/atmosphere/hbl.nsp.
  - Rename sdmc:/switch/ds2/logs to logs_test18 (or any free name).

Test 19 (own system resource)
  - Open sdmc:/atmosphere/config/override_config.ini (create it if missing; make a copy first if it exists).
    In the [hbl_config] section (add the line "[hbl_config]" if there is none) add the line:
        path=atmosphere/hbl_ds2.nsp
  - Reboot the console (the setting is read at boot).
  - Start ds2.nro from the Homebrew Menu holding R on a game (title takeover), as before. Continue or New Game.
  - If the level loads: walk a few steps, wait 2-3 minutes, then exit with HOME -> close.
    If it hangs: wait 1 minute, note what you see, exit the cleanest way that works.
  - Copy sdmc:/switch/ds2/logs to the Mac as ds2_logs/diag12/toml19/ and rename the SD folder to logs_test19.

Test 20 (stock hbloader, same NRO and toml) - checks whether the NRO alone is now enough
  - In override_config.ini delete the path= line (or restore your copy). Reboot.
  - Start the same way. If the level loads, play 2-3 minutes as in test 19; if it hangs, exit.
    Copy the logs to ds2_logs/diag12/toml20/.

Reverting completely: remove the path= line from override_config.ini (or restore the copy), reboot; you may delete
sdmc:/atmosphere/hbl_ds2.nsp. Nothing else on the SD card is changed.

What to send: the logs folder of each test (ds2_*.log, rex/*.log), any new sdmc:/atmosphere/crash_reports/ files,
and a line on what happened (loaded into the world or not; how you exited).
