DS2 Switch - diag3, tests 4 and 5
=================================
diag3 = diag2 + logs/ds2_wd_last.txt: rewritten and committed to the SD card every 2 s, so it survives a forced
power-off and says when the game was last alive and which files it had just opened.

Why: in tests 1 and 3 the log stops ~1 s after the level starts loading, right after an NVK
"submission pressure" warning (the GPU stopped accepting work). In test 2 (two changes at once: uniform-buffer path
NVK_SWITCH_NO_UBO_CBUF=1 and Mesa shader cache off) there was no such warning and the game kept working: the GPU
command thread kept compiling the level's shaders (about 2 per second) and the log goes on for another minute.
Tests 4 and 5 separate the two changes.

Setup: copy ds2.nro (sha256 in ds2.nro.sha256) to sdmc:/switch/ds2/ds2.nro (keep ds2_v1.nro). Overlay may stay off.
For each test: put the toml as sdmc:/switch/ds2/ds2.toml, rename the logs folder of the previous test.

Steps (same for 4 and 5):
  1. Continue -> loading -> intro movie -> loading screen.
  2. From the moment the loading screen with the water sound appears, WAIT 10 MINUTES. Note the clock time
     when it appeared, and whether/when the picture appears.
  3. Every ~2 minutes press HOME once: does the HOME menu open? (if it opens, go back to the game).
     This tells "the game is slow" (HOME works) from "the whole console froze" (HOME does nothing).
  4. Exit with HOME -> Close if possible; power-off only if HOME does not work. Note which.
Send: the whole sdmc:/switch/ds2/logs folder (now includes ds2_wd_last.txt) + notes.
