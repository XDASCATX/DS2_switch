# 18. Сторонние проекты и путь к 30–60 кадр/с: что применимо к DS2

Изучено 2026-10-22 по исходникам, истории и документации (не по README). Что из этого замер, а что оценка — помечено.

## Где мы сейчас (замеры v34 на консоли, `diag_toml34`)

- Консоль разогнана: в `rex_perfil.log` частоты GPU 1228.8 МГц, CPU 2397 МГц, память 2500 МГц
  (штатно в доке 768 МГц GPU). Все FPS ниже — при этом разгоне.
- GPU занят на 100 %: 90–165 мс GPU на кадр. В тяжёлой сцене (t=270–290 с): переносы EDRAM ~57 мс (42 %),
  draw игры ~62 мс, resolve + загрузка текстур ~15 мс.
- Поток команд GPU — 15–23 % CPU, основной поток игры — 95–98 % (на чём крутится — v35 снимет стеки).

Оценка (не замер): даже убрав все переносы EDRAM, эмуляция Xenos остаётся на ~70–100 мс GPU в тяжёлых сценах
при разгоне, то есть ~10–15 кадр/с; 30 кадр/с на штатных частотах на этом пути не просматривается. Для
сравнения nfsmw-nx: эмуляция ReXGlue — 2 кадр/с, свой рендерер — 30–35 кадр/с на штатных частотах.

## Проекты

### nx-mod/rexglue-sdk-nx (2026-10-18, 666 коммитов)

- ReXGlue v0.10.0 + слой Switch из nfsmw-nx + **рендерер на deko3d** (`src/x360/deko`, `include/rex/x360`, ~10 тыс.
  строк) вместо эмуляции Xenos. Рендер на Switch «только deko3d, никогда Vulkan» (`switch/PORTED.md`).
- Архитектура (`destinos.h`, `render.h`): читает PM4 игры, render target = обычная картинка на (база, формат, pitch),
  EDRAM не эмулируется, resolve = копия в текстуру (или обмен картинками без копии), текстуры по отпечатку XXH3
  байтов с редкой перепроверкой, шейдеры — готовая библиотека SPIR-V из XenosRecomp, на консоли SPIR-V → GLSL
  (SPIRV-Cross) → DKSH (uam) с кэшем. Игра подключает `RenderHooks` (классификация проходов, варианты шейдеров).
- Состояние по их же документам: NFSMW работает; Halo 3 — «до меню, без геометрии»; не сделаны кубкарты из
  resolve, отложенное небо, occlusion queries. То есть «универсальность» пока на одной игре.
- Применимо к DS2: да, как основа своего рендерера. Не применимо «как есть»: DS2 использует light pre-pass,
  4xMSAA и переинтерпретацию одного EDRAM как 4x и 1x (на ПК в интро главный перенос — `C0x1 p16 b0 <- C0x4 p16 b0`),
  этого в их рендерере нет — нужна своя логика для DS2.
- Наш SDK — другая ветка (из nfsmw-nx, Vulkan); перенос их рендерера = перенос `x360/` + `ui/deko3d` + сборка
  deko3d/uam/SPIRV-Cross под devkitA64 (в нашем devkitPro deko3d не установлен).

### rexglue/rexglue-sdk (основной)

- `main`/`development` с августа: в графике почти ничего (MoltenVK, кэш-пути), в кодогенерации — `stwcx.` через
  `std::atomic` CAS, барьеры `sync/lwsync/eieio`, исправления `vpkuwus`. Это корректность CPU-кода; на скорость GPU
  не влияет. Перенос — только если увидим ошибки этих инструкций.

### hedge-dev/XenosRecomp

- Переводит шейдеры Xbox 360 (контейнеры `0x102A11xx`) в HLSL, дальше DXC → SPIR-V. Сделан под Unleashed Recompiled
  (жёсткие vk::location, без mini-fetch, без целочисленных констант).
- **Проверено на шейдерах DS2** (извлечены локально из `shader/*.bnd`, BND4 + zlib; не публикуются):
  2275 шейдеров (`.fpo`/`.vpo`, все в формате `0x102A1100/01`), HLSL получен для **2271** (4 падения — vfetch
  точечных спрайтов без элемента объявления), DXC (renderbag/dxc-bin, Linux) собрал SPIR-V для **2166 (95 %)**.
  Ошибки: 94 — нет vk::location для TANGENT1 и т. п. (таблица Unleashed), 9 — 3D/объёмные сэмплеры
  (`ToneMapTableSampler`), 4 — `iColorN`. Всё это известные ограничения, правятся в переводчике.
- Форк nfsmw-nx (`nfsmw-nx/shaders/XenosRecomp`, `NFSMW_RECOMP`) — под контракт их рендерера (g_InputRemap,
  ветка deko3d в shader_common.h); для DS2 брать его за основу.

### switchbrew/libnx, devkitPro

- Каналы GPU и GPFIFO — через `nvGpuChannel*` (используются в mesa-switch). Давление на GPFIFO у нас устранено в
  v34 (UBO напрямую), поэтому менять libnx нет нужды.
- deko3d (devkitPro) — нативный API Maxwell на Switch с минимальной ценой вызова на CPU; uam — компилятор GLSL → DKSH
  на основе старого nouveau-codegen Mesa (не NAK).

### DirectXShaderCompiler, Vulkan SDK

- DXC нужен только для шага HLSL → SPIR-V библиотеки шейдеров (на ПК). Linux-бинарь берётся из renderbag/dxc-bin
  (релизы GitHub из контейнера недоступны).
- Vulkan SDK: spirv-val / spirv-cross / glslang уже есть в системе; для проверки библиотеки шейдеров этого достаточно.

## Что применимо к эмуляции уже сейчас (сделано или в работе)

- v34: UBO из обычного набора дескрипторов напрямую (NVK) — подтверждено на консоли: 0 ожиданий GPFIFO вместо 3477.
- v35: разреженный (sparse) буфер общей памяти в NVK — 512 МБ кучи не выделяются сразу (на ПК в интро 160 МБ).
- Из nfsmw: ZCULL в нашем NVK уже включается для глубины xenia (usage SAMPLED|DEPTH_STENCIL_ATTACHMENT);
  отпечатки текстур и редкая перепроверка — идея для texture cache xenia (44 загрузки текстур на кадр в v34).

## План (оценка трудоёмкости — не замер)

1. Эмуляция: по данным v35 (барьеры по местам, виды переносов в тяжёлой сцене, стеки основного потока) — убрать
   лишние переносы и барьеры, крутящееся ожидание игры.
2. Свой рендерер DS2 (долгий путь, недели):
   - этап 0 — библиотека шейдеров DS2: форк XenosRecomp, 100 % шейдеров, упаковка по отпечатку; проверка SPIR-V;
   - этап 1 — опознание шейдеров в PM4 по маскированному микрокоду (как `EntradaShader::huella`), счёт
     попаданий на ПК в трассе эмуляции;
   - этап 2 — перенос `rex::x360` + deko3d (или Vulkan-вариант nfsmw для отладки на ПК) в наш SDK;
   - этап 3 — проходы DS2 (light pre-pass, тени, MSAA-переинтерпретация) с проверкой по кадрам эмуляции на ПК.
