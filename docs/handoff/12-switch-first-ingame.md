# 12. Первый вход в игровой мир на Switch (2026-10-20, тест 21)

На реальной Nintendo Switch (Atmosphère, title takeover через стандартный hbloader) DS2 SotFS загрузил локацию:
видна вступительная сцена, персонаж управляется, открывается меню настроек. Состояние — «полу-рабочее»:
~1 кадр в секунду, красноватый оттенок 3D (как на ПК).

## Сборка
- Ветка `diag/switch-level-load`, ветка-снимок `switch/ingame-1` (тег `switch-ingame-1` только локально: прокси не пропускает теги); NRO = `releases/diag12` (sha256 `39a08daa…906b`, в GitHub
  не публикуется: производное от игры).
- Тулчейн и Mesa — `docs/handoff/10-switch-build.md`.
- Настройки — `config/toml-history/11-ds2.toml.test21` (обязательно `host_thread_stack_mb = 6`).

## Что сняло блокеры (подробно — `11-switch-level-load-diag.md`)
1. 2001-0103 при загрузке уровня: процесс под hbloader без своего системного ресурса берёт таблицы страниц из
   общей с системой кучи ядра. Гостевая память SDK требовала таблицу на каждые 2 МБ: окно и теневые отображения
   стояли на случайных 4-КБ адресах (`virtmemFind*` принимает защитную зону, а не выравнивание), память
   подтверждалась сотнями мелких кусков. Исправлено выравниванием по 2 МБ и гранулой 2 МБ (SDK,
   `guest_memory_switch.cpp`); проверено симулятором `tools/switch/gm-sim` (2103 → 512 таблиц).
2. Нехватка кучи (отказ `memalign` в NVK → чёрный экран): 44 стека гостевых потоков по 16 МБ (741 МБ) при реальном
   использовании ≤ 3,6 МБ. `host_thread_stack_mb = 6` (cvar SDK, `xthread.cpp`).
