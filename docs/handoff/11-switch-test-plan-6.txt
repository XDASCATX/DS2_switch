DS2 Switch - diag7, test 11 (first attempt at a fix)
=====================================================
Test 10 answered the question. At the failure (10,799 memory blocks) the biggest group is
"window type=0x0F perm=3": 7,214 blocks covering 979 MB - the mirrors (views) of the game's memory, cut into
thousands of separate mappings. Protection holes are only 84. So the blocks are not textures or GPU buffers: every
page the write watch unmaps and later maps back stays a separate small mapping forever, and they pile up until the
kernel runs out (2001-0103).

diag7 changes the SDK's guest memory code (sdk/src/core/guest_memory_switch.cpp) for this: after a page is mapped
back, the whole run of unprotected pages around it is remapped with one call, so it is one block again. The
heartbeat now also shows merged_runs= and merge_fail= (how many runs were merged, how many attempts failed).

Setup: copy diag7/ds2.nro as sdmc:/switch/ds2/ds2.nro, ds2.toml.test11 as ds2.toml, rename the old logs folder.
Do not open the overlay. Same steps: Continue -> intro -> loading. If the world appears, try to walk for a minute.
If the screen stays black, wait 3 minutes. Exit with HOME -> Close if it works. Send the whole logs folder + notes.
If the game crashes right away (an error screen) note it and send logs/rex/rex_crash.log too.
