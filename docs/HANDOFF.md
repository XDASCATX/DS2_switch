# DS2 SotFS → Nintendo Switch: передача работы (текущее состояние)

**Обновлено: 2026-10-23, после выдачи v56.** Обновлять после каждой версии и после каждого отзыва владельца
(разделы 2, 3, 5, таблица в 4). Точка входа для ИИ — [../CLAUDE.md](../CLAUDE.md); индекс документов —
[README.md](README.md).

## 1. Проект в двух строках

Порт Dark Souls II: Scholar of the First Sin (Xbox 360, TitleID 465307E4) на Nintendo Switch статической
рекомпиляцией (ReXGlue: `Default.xex` → C++ → NRO, devkitA64) с собственным Vulkan-рендерером на NVK.
**Цель сейчас (владелец): стабильные 30+ кадр/с везде, желательно без предельного разгона.**

## 2. Состояние

**Работает (подтверждено на консоли владельца):** на нативном рендерере (v53–v55) — запуск, меню, загрузка
сохранения, Маджула, вторая локация, бой, смерть, подгрузка локаций без вылетов; картинка по оценке владельца лучше
старой эмуляции; частоты сессии из TOML (v55); снимок кадра L3+R3 (v55). Вступление, редактор персонажа и путь до
Маджулы проверены на эмуляционном пути (v46–v50); на нативном отдельно не проходились.

**Не достигнуто / дефекты (консоль):** ~20 кадр/с (нужно 30+); просадки до 8 при подгрузке; свет костра у торговки
не освещает объекты; лут светится сквозь стены. Подробно — [known-issues.md](known-issues.md).

**Узкое место по замерам v55:** CPU, не GPU. GPU 31–36 мс/кадр; поток команд GPU ~34 мс CPU на кадр; главный поток
игры ~25 % в ожидании общего мьютекса областей mtmsrd. ([performance.md](performance.md))

**v56 (выдана, ждёт теста):** разгрузка CPU (без общего мьютекса mtmsrd, dynamic UBO, повтор наборов
дескрипторов, быстрая запись регистров, раздвижка тайлов, кэш sub-resolve), FMA в пиксельных шейдерах, профиль GPU
по вызовам. На ПК: меню и Междумирье рисуются верно. На консоли — **не проверено**.

## 5. Открытые задачи (по приоритету)

1. **Разобрать тест v56** (когда пришлёт логи): FPS по блокам (`tools/analysis/threads.py --list`), CPU потоков
   `GPU Commands` и `Main XThread`, `[native] cpu ms per frame`, `[native gpu]`, `[native gpu draws]`, `hitch`.
   Критерий — понять, где теперь предел (CPU потока команд / главного потока / GPU) и на сколько.
2. **30+ кадр/с** (главная задача). Кандидаты — [performance.md §6](performance.md#6-известные-резервы-не-сделано):
   настоящий 4xMSAA для целей 4x, кэш вершинных буферов, push-дескрипторы, оптимизация горячих шейдеров по
   `[native gpu draws]`, офлайн-библиотека шейдеров. Критерий — ≥30 кадр/с в Маджуле (вид на город) и в бою на
   частотах TOML, подтверждено владельцем.
3. **Просадки при подгрузке** — по строкам `hitch` v56. Критерий: нет кадров >100 мс вне экранов загрузки.
4. **Свет костра у торговки** — есть снимок `diag_toml55/capture_01` (у владельца; разбор в known-issues).
   Следующий шаг — найти draw костра (сфера 136 индексов, ps `3222F018…`) и проверить глубину/трафарет D1@720.
5. **Лут сквозь стены** — попросить снимок L3+R3 там, где видно.
6. Затем — снижать частоты TOML (цель владельца — лёгкий профиль).

## 6. Что уже пробовали (не повторять вслепую)

- Оптимизацию эмуляции EDRAM (v30–v50) — потолок ~15 кадр/с.
- Настоящие occlusion queries с запаздыванием (v54) — мигание врагов → выключены.
- Барьер перед каждым проходом (v51–v54) — убран в v55 (ключ для проверки остался).
- FSI-путь эмуляции — зависание (тест 24).
- hbloader с системным ресурсом (тест 19) — не запустился.
Полностью — [history.md](history.md), [decisions.md](decisions.md).

## 7. Состояние исходников и окружения

- Git: ветка `diag/switch-level-load`, всё закоммичено и отправлено в origin (github.com/XDASCATX/DS2_switch).
  Копия-репозиторий владельца (`SW1_ds2` на Mac) **не обновлялась с v51** (`git pull` требует права удалять файлы
  на Mac, которых у сессии нет) — сборки и TOML туда передаются файлами.
- Не в git (по правилам): файлы игры (`assets/`, `out/run/game_root`), сгенерированный код (`app/generated/`,
  ~350 МБ, перегенерация — часы), сборки (`out/`, релизы с ELF), дерево и SDK Mesa (`/home/claude/swtc`),
  тулчейн (`/opt/devkitpro`). Перенос окружения — [migration.md](migration.md).
- Папка `_to_delete/` на Mac — части передач и старые архивы логов, их можно удалить вручную.

## 8. С чего начать новому исполнителю

1. Прочитать [../CLAUDE.md](../CLAUDE.md), этот файл, [known-issues.md](known-issues.md), [performance.md](performance.md).
2. Проверить окружение: `. tools/build/env.sh; tools/build/compile-check.sh sdk/src/graphics/native/native_renderer.cpp`.
3. Если пришли логи v56 — задача 1. Если нет — задача 2 (без консоли можно готовить изменения и проверять на ПК,
   но выдавать как vNN только с ПК-проверкой кадра в игре).

## 9. Правила (кратко; полностью — CLAUDE.md)

Писать владельцу по-русски и коротко; `Default.xex` и прошлые версии не менять; ничего из игры не коммитить;
работать в `diag/switch-level-load`; «исправлено» — только после консоли; замеры отделять от предположений;
тестовые переключатели — через один TOML; длинные автопрохождения не делать.
